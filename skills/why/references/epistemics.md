# Historical-evidence epistemics

Use this before turning fragments into a design-rationale narrative.

## Evidence classes

- **Direct.** A contemporaneous artifact explicitly states the reason, constraint, tradeoff, rejected alternative, or incident link.
- **Corroborated inference.** Multiple independent signals support the same explanation, but no source states it directly.
- **Weak inference.** The explanation is plausible from timing or code shape but has little independent support.
- **Unknown.** Available evidence cannot distinguish the plausible explanations.

## Rules

1. Cite direct claims to an artifact actually read.
2. Label inference as inference. Prefer `appears to`, `likely`, or `suggests` when the record is indirect.
3. Surface contradictions. Do not silently choose the source that makes the cleanest story.
4. Preserve null results. `Searched issue tracker; no matching decision record found` is useful evidence.
5. Name unavailable categories separately from searched-empty categories.
6. Do not retrofit current architectural good sense into historical intent.
7. When several explanations fit, present competing hypotheses and what evidence would distinguish them.

## Confidence

Use `HIGH` only when direct evidence is explicit and materially consistent. Use `MEDIUM` when the explanation is strongly corroborated but indirect. Use `LOW` when substantial gaps or competing explanations remain. If the decisive record is unavailable, say `INCONCLUSIVE` rather than manufacturing certainty.
